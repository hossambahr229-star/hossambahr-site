# البنية الإنتاجية لمنصة Hossam Bahr

## القرار المعماري

يبقى الموقع الحالي واجهة المعرفة العامة أثناء الانتقال، وتُشغّل الوظائف الحساسة في بيئة سحابية منفصلة داخل دولة الإمارات. البنية المستهدفة هي:

- واجهة الويب: Azure Static Web Apps أو Azure App Service.
- واجهة البرمجة: Azure Functions خلف Azure API Management.
- قاعدة البيانات: Azure Database for PostgreSQL.
- المستندات: Azure Blob Storage بحاويات خاصة وروابط رفع وتنزيل قصيرة الصلاحية.
- الهوية: Microsoft Entra External ID مع تحقق متعدد العوامل للموظفين.
- الأسرار والمفاتيح: Azure Key Vault.
- المراقبة: Application Insights مع تنقية البيانات الحساسة من السجلات.
- المنطقة الأساسية: UAE North، مع نسخ احتياطي وخطة استعادة مناسبة داخل النطاق المعتمد.

لا تُحفظ الجوازات أو الهويات أو العقود أو بيانات الدفع في GitHub Pages أو المتصفح أو المستودع البرمجي.

## رحلة العميل الإنتاجية

1. ينشئ العميل حساباً ويتحقق من وسيلة الاتصال.
2. يختار الخدمة ويشاهد تقديراً مفصولاً للرسوم الحكومية ورسوم المنصة.
3. ينشئ طلباً ويحصل على رقم مرجعي غير قابل للتخمين.
4. ترفع المستندات مباشرة إلى التخزين الخاص عبر رابط موقّع قصير الصلاحية.
5. يراجع موظف مخوّل الطلب ويسجل النواقص دون تنزيل غير ضروري.
6. ينشئ الخادم جلسة دفع لدى مزود معتمد؛ لا تمر بيانات البطاقة عبر المنصة.
7. تؤكد بوابة الدفع النتيجة عبر webhook موقّع ومقاوم للتكرار.
8. تسجل كل حركة في سجل تدقيق غير قابل للتعديل من الواجهة.
9. يتابع العميل الحالة والتنبيهات من حسابه، لا من خلال رقم الهاتف وحده.

## حالات الطلب الموحدة

`draft` ← `submitted` ← `under_review` ← `awaiting_documents` أو `ready_for_payment` ← `in_progress` ← `awaiting_authority` ← `completed`

ويجوز الانتقال إلى `cancelled` أو `rejected` مع سبب مسجل. لا يسمح بتخطي المراحل الحساسة دون صلاحية ومبرر في سجل التدقيق.

## الصلاحيات

- العميل: يرى شركاته وطلباته ومستنداته فقط.
- ممثل الشركة: يدير ما تسمح به عضويته داخل شركة واحدة أو أكثر.
- منفذ المعاملة: يرى الطلبات المسندة إليه والحد الأدنى من المستندات اللازمة.
- المراجع: يعتمد الجاهزية والرسوم والتغييرات الحساسة.
- المحاسب: يرى الفواتير والمدفوعات دون محتوى المستندات.
- المدير: يدير الفريق والسياسات، ولا يحصل تلقائياً على صلاحية تصفح كل مستند.
- المدقق: يقرأ سجل التدقيق فقط.

## بوابات الإطلاق

### البوابة 1 — أساس آمن

- اشتراك Azure باسم المنشأة وبيئة اختبار وبيئة إنتاج منفصلتان.
- نطاق فرعي للمنصة وشهادات HTTPS وسياسة محتوى آمنة.
- حسابات وصلاحيات وقاعدة بيانات وتخزين خاص وسجل تدقيق.
- اختبارات نسخ احتياطي واستعادة وفحص برمجيات خبيثة للملفات.

### البوابة 2 — الطلبات الحقيقية

- كتالوج خدمات مركزي بإصدارات للرسوم والمتطلبات.
- إنشاء طلب، رفع مستندات، مراجعة، حالات وتنبيهات.
- لوحة تشغيل داخلية وتقارير زمن الإنجاز والنواقص.

### البوابة 3 — الدفع

- عقد تاجر مع مزود دفع مرخص ومراجعة قانونية لشروط البيع والاسترداد.
- فصل كامل بين الرسم الحكومي ورسم المنصة في العرض والفاتورة.
- webhooks موقعة، مفاتيح تكرار، تسوية يومية، واسترداد موثق.

### البوابة 4 — النمو والتحسين

- صفحات خدمات مولدة من قاعدة بيانات بعد مراجعة بشرية.
- مساعد يعتمد على مصادر رسمية مؤرخة ويعرض مصدر الإجابة وحدودها.
- سوق أعمال بمزودين موثقين وإفصاح واضح عن العمولة والتقييمات.
- قياس التحويل ورضا العملاء وزمن الإنجاز، ثم تحسين التجربة وفق بيانات حقيقية.

## معايير النجاح قبل وصف المنصة بأنها مكتملة

- لا توجد ثغرات عالية الخطورة في فحص مستقل.
- نجاح اختبار الاستعادة من النسخ الاحتياطية.
- كل طلب ومستند ومدفوع له أثر تدقيق كامل.
- نسبة نجاح الدفع، وزمن الاستجابة، وتوفر الخدمة لها أهداف معلنة ومقاسة.
- الرسوم والمتطلبات مرتبطة بمصدر رسمي وتاريخ تحقق ومسؤول مراجعة.
- تجربة الهاتف واجتياز الوصول الأساسي بالعربية والإنجليزية.
- موافقة قانونية على الخصوصية والشروط والاحتفاظ ونقل البيانات.
